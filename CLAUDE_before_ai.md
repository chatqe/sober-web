## Project Overview

**qs-web** is a personal blog/community SPA built with Vue 3. It includes a public-facing frontend (articles, notes/说说, favorites with music/friendship/collections, travel footprint,留言板) and an admin panel for managing content, users, comments, and site configuration.

## Key Commands

```bash
pnpm dev              # Start Vite dev server (http://localhost)
pnpm build            # Build for production
pnpm preview          # Preview production build locally
pnpm orval            # Regenerate API clients from Swagger (http://localhost:18081/v3/api-docs)
pnpm orval:watch      # Watch mode for orval generation
```

## Architecture

### Layered API Pattern (3 layers)

1. **Generated (`src/api/generated/`)** — Auto-generated by Orval from Swagger JSON. One file per API tag (e.g., `admin-article.ts`, `user.ts`). Uses a shared Axios instance and response/error handlers.
2. **Manual (`src/api/manual/`)** — Hand-written API modules used alongside generated ones (currently empty but the directory exists).
3. **Re-export (`src/api/modules/index.ts`)** — Barrel re-exports from `src/api/modules/*.ts` files (legacy `.js` files are being migrated to `.ts` on the `dev_20251225_add-ts` branch).

**API client setup**: `src/api/client/axios.ts` creates a singleton axios instance (`baseURL: VITE_BASE_URL`, 30s timeout, credentials included). `src/api/client/responseHandler.ts` provides `handleResponse` (extracts `response.data`) and `handleError` (unified error logging + status code handling) — these are injected as Orval's `mutator` and `errorHandler`.

### Routing

`src/router/index.ts` defines two route groups:
- **Public routes** (`/` with children) — 10+ sub-pages rendered via lazy-loaded components under a shared home shell.
- **Admin routes** (`/admin/*`) — Protected by `requiresAuth: true` meta; the global `beforeEach` guard checks `useAuthStore().adminToken` and redirects to `/verify` if missing.

Route metadata (`gradDir`, `visible`) is centralized in `src/router/metaCfg.ts` for UI concerns like gradient backgrounds and navigation visibility.

### State Management

Pinia stores (`src/stores/modules/`) with `persist: true` (persisted to localStorage):

| Store | Purpose |
|-------|---------|
| `auth` | userToken / adminToken / isAdmin |
| `user` | Current user profile |
| `webInfo` | Site info (title, description, etc.) |
| `sysConfig` | System configuration |
| `sortInfo` | Category/tag info |
| `toolbar` | Toolbar state |
| `footer` | Footer state |

All stores exported from `src/stores/index.ts`.

### Component Organization

- **`src/components/`** — Most "pages" are actually single-file components here (index, article, weiYan, love, sort, travel, etc.), not route-level views. This is a design choice of this project.
- **`src/components/admin/`** — Admin panel components (post list/edit, user list, comment list, sort list, etc.) under a shared admin layout (`admin.vue`).
- **`src/components/auth/`** — Login, Register, ResetPwd forms extracted from the global AuthModal.
- **`src/components/comment/`** — Comment list and graffiti board.

### Style & UI

- **Element Plus** with SCSS import style. Custom theme overrides in `src/style/el-custom.scss`.
- Auto-imports configured in `vite.config.js`: Vue APIs, Element Plus components, and Iconify icons (`ep` collection with `Icon` prefix).
- Shared CSS in `src/assets/css/` (color.css, animation.css, index.css).

### TS Migration Status

On branch `dev_20251225_add-ts`:
- `strict: false`, `noUnusedLocals: false`, `noUnusedParameters: false` — migration is incremental.
- Some files in `src/api/modules/` are still `.js` (marked `AD` in git status), others migrated to `.ts` and old `.js` deleted (`D`).
- When adding new TS code, prefer `<script setup lang="ts">` in Vue SFCs and add proper type annotations.

### Key Patterns

- **Lazy route loading**: All route components use `() => import('../components/...')`.
- **Global provides**: `main.ts` injects `$common` and `$constant` via `app.provide()` for cross-component access.
- **IM/Realtime**: Uses SockJS + custom `live2d.js`, `sakura.js`, `bubble.js` for interactive visual features and websocket chat.
- **Content editing**: TinyMCE for admin posts, md-editor-v3 for markdown.
